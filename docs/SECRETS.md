# Credentials and public configuration

No secret values are committed or exported in platform-contract-v2. Terraform
creates Secrets Manager metadata only. Operators seed values externally.

| AWS secret suffix | Required JSON properties | Consumers |
|---|---|---|
| processing/business/drift/mlflow/knowledge-database | url, username, password, credential_json | only matching owner; bootstrap operation |
| ingestion-auth | api_key | Sensor and Ingestion |
| processing-api-auth | api_key | Business, Drift and Processing Read API |
| ml-api-auth | api_key | Processing Worker and ML |
| rag-api-auth | api_key | Business and RAG |
| llm-provider | api_key | RAG only |
| model-release-publisher | app_id, installation_id, private_key | training publish task only |
| gitops-automation | operator-managed App metadata | reserved; CI token uses GitHub secret |

credential_json is a JSON string containing that owner's username/password, not
admin credentials. Keep it consistent with url and the actual database role.
Use sslmode=verify-full and the mounted `/etc/rds-ca/global-bundle.pem`; MLflow URL
must be compatible with its SQLAlchemy PostgreSQL driver. Cloud RDS admin secret
is projected only by `operations/database-bootstrap`, never a normal app root.

Populate platform/secrets/rds-ca.yaml with the reviewed public AWS RDS CA bundle
and record its SHA-256 in config/trust.json before DB-client activation. CA public
material is not a password. No runtime downloads an unpinned CA or disables TLS.

Kafka passwords are generated by Strimzi KafkaUser resources in namespace maintai.
Clients mount its cluster CA and use dedicated SCRAM users. Ingestion can publish
sensor.readings; Processing/Storage consume their groups; Outbox writes results/
signals; Business consumes only its three groups. These are service identities,
not user login tokens.

GitHub Apps must be separate identities: app-image publisher, platform handoff
publisher, model-release publisher, automation-image publisher (Actions write),
and GitOps PR automation (Contents/PR write). Receiver actor allow-lists must match
installed App bot actors, not payload claims. Recovery may allow the owner login.
Private keys live in GitHub protected secrets or AWS Secrets Manager, never JSON
contracts. Do not put the model publisher key in train/prepare pod environment.

GitHub variables: ENABLE_GITOPS_AUTOMATION (initially false), ENABLE_IMAGE_PUBLICATION
(false), AWS_REGION, GITOPS_READER_ROLE_ARN, IMAGE_REPOSITORIES_JSON,
GITOPS_IMAGE_PUBLISHER_ROLE_ARN, *_RELEASE_ALLOWED_ACTOR, RECOVERY_ALLOWED_ACTOR,
GITOPS_APP_ID/INSTALLATION_ID and publisher App IDs. Private keys are GitHub secrets.

Business/Sensor use a reviewed external OIDC issuer and audience. UI client IDs
are public; Simulator UI gets no service API key. Management ALB CIDRs and API-side
simulator.control authorization are both required. Main UI has no control route.
