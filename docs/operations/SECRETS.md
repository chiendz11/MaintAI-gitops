# Credentials and Secret Management

No real secret values, passwords, PATs, or TLS private keys are committed in `MaintAI-gitops`. External Secrets Operator (`ESO`) projects runtime secrets from AWS Secrets Manager (or LocalStack in local `k3d`) into Kubernetes Secrets.

| Secret suffix | Required JSON properties | Consumers |
|---|---|---|
| `processing/business/drift/mlflow/knowledge-database` | `url`, `username`, `password`, `credential_json` | matching owner DB client only |
| `ingestion-auth` | `api_key` | Sensor and Ingestion |
| `processing-api-auth` | `api_key` | Business, Drift and Processing Read API |
| `ml-api-auth` | `api_key` | Processing Worker and ML |
| `rag-api-auth` | `api_key` | Business and RAG |
| `llm-provider` | `api_key` | RAG only |

## TLS, Kafka & GitOps Credentials

- **Database TLS:** Use `sslmode=verify-full` with mounted RDS CA bundle in production; owner `credential_json` must match the owner DB role (never share admin credentials across owner runtimes).
- **Kafka SCRAM Users:** Generated by Strimzi `KafkaUser` in production or configured per service identity in local `k3d`; clients mount the cluster CA and never share user login tokens.
- **OIDC Clients:** Main UI and Simulator UI use public PKCE client IDs (zero internal service keys or LLM keys exposed to browser JS).
- **Argo CD Image Updater (`argocd-image-updater-git-creds`):** Fine-grained PAT (repository: `chiendz11/MaintAI-gitops`, `Contents: Read & Write`, `Pull requests: Read & Write`) stored directly in Kubernetes Secret `argocd-image-updater-git-creds` inside namespace `argocd`. Provisioned at bootstrap by `Maint-infrastructure` (`python -m localdev image-updater-pat`) or KMS/ESO, never committed to Git.
